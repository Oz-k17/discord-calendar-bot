- **合成の声が平板すぎる** — `speak()` は発話中ずっと倍音の重みも f0 も固定で、
  形の上ではトレモロの楽器と同じもの。`vowel: true` を足したが既定は従来のまま
  （過去の数字と比べられなくなるため）。いつか既定を切り替えるなら、
  そのときは全部の数字を測り直すことになる。
- **本物の声・本物の音楽で試す** — 試し用の素材はすべて自分で作った合成音。
  意地悪な素材を足して思い込みは潰したが、それも自分の想定の内側でしかない。
- **ラウドネス正規化（LUFS）** — SNS の再生音量に合わせて -14 LUFS へ揃える。
  書き出しの最後に 1 回かけるだけなので、実装は軽いわりに効果が大きい。
- **クリップごとの音量の自動合わせ** — 複数のカットで声の大きさがバラバラなのを揃える。
- **ビート検出（BPM）** — 曲に合わせてカットを置きたいときの下地。
  タイムラインのスナップ先にビートを足せると強い。

### 映像まわり

- **シーン検出** — 素材の中でカットが切り替わっている場所を見つけて、自動で分割する。
  隣り合うフレームの差分を見るだけなので、考え方は無音カットとほぼ同じ。
- **被写体を追う自動リフレーム** — 横型素材から縦型を切り出すとき、
  人物や動きのある場所を追いかけてクロップ枠を動かす。本体のクロップの真上に乗る。
- **サムネイル候補の自動抽出** — ブレていない・情報量の多いコマを何枚か出す。
- **キーフレーム（時間で変化する値）** — 拡大・位置・不透明度を時間で動かす。
  本体のモデルに手が入るので、まずラボで「値の持ち方」を試したい。

### 2026-09-10（1 回目） — 音楽だけの素材を切り刻む穴を塞いだ（積み残しの筆頭）

- **`music-tremolo.wav`（4.5Hz で震える和音だけ・声なし）を足した。** これが当日の判定を 2 回壊した。
- 「スペクトルの形の変化」（`shapeFlux`）を足した。正規化してから比べるので**音量倍率に不変**。
- **素材単位**で「どこかで形が動いたか」を見て、動かなければ何もしない（`noSpeechReason: 'shape'`）。

**測った結果**

声の無い素材（ここが今回の本題）:

| 素材 | 前 | 後 |
| --- | --- | --- |
| `bgm.wav`（音楽だけ） | **削減 64% / 精度 0%**（全部誤り） | **0%・何もしない** |
| ※ `music-tremolo.wav`（震える楽器） | 声らしさ **100%**（声が無いのに満点） | **0%・何もしない** |
| ※ `drums.wav` | 0%・何もしない | 0%・何もしない |

**声のある素材は 9 本すべて、前後で数字が 1 つも変わっていない**
（削減 12〜50% / 残せた率 99〜100% / 精度 40〜90%、素材によって幅がある）。
つまり今回は、**害だけを取り除いて、効きは 1 つも損なっていない**。

**分かったこと**

- **候補に書いてあった「区間の長さの分布」は駄目だった。** 2 段階で測って 2 段階とも外れ。
  素の判定コマの連続長は音量ゲートに支配されていて、本物の声のほう（`speech-noisy` 最長 0.22 秒）が
  音楽だけ（1.14 秒）より細切れになる。まとめたあとの区間で見ると、
  まとめる工程（`minSilence` + `padding`）が長さの差を消してしまい、
  音楽だけ 2.06 秒 / たまにしゃべる 2.40 秒でほぼ同じになる。
- **「声らしさが高いコマがあるか」も駄目だった。** いったんは分かれて見えた
  （声なし最大 0.40 / 声あり最小 0.535）が、`music-tremolo.wav` を作った瞬間に壊れた
  （中央値 0.896・割合 100% で、本物の声のどれよりも高い）。
  **`speechScore` から作る統計量は、どう捏ねても震える楽器を弾けない。**
  声らしさの定義が「音程のある音が音節の速さで揺れている」なので、
  震える楽器はその定義に**完全に当てはまる**。定義の外から手がかりを持ってくるしかない。
- **検算が穴をそのまま肯定していた。** 落ちたテストを見に行ったら、
  「声らしさの代表」として使っていた合成音が **200Hz の正弦波を音量だけ揺らしたもの**、
  つまり `music-tremolo` そのものだった。テストが仕様として穴を固定していた形。
- **コマ単位の門は筋が悪かったので引き返した。** 掛け算で打ち消す形は、測った限りでは
  とても良く見えた（声コマを残せた率 99.1% のまま、声なし素材での誤検出 37.2% → **0.0%**。
  `speech-sparse-bgm` の精度が 40% → **81%**、`speech-bgm-loud` が 63% → **89%**）。
  ところが**背景のほとんど無い素材を作って掛けたら、声を半分以上切り落とした**（100% → 46%）。
  乾いた素材では発話中の形の変化が 0.011〜0.046 までしか上がらず、震える楽器（0.071 まで）より
  下に来る。**絶対値では線が引けない。** 惜しかったが、声を切るのは取り返しがつかないので捨てた。
- **同じ量でも「素材のどこかで動いたか」なら分かれる。** 声なし 0.00 秒に対し、
  声のある素材はいちばん少ない乾いた録音でも 1.78 秒。**開きが 2 倍以上ある。**
  コマごとに「毎回動いていること」を求めると無理だが、
  「一度でも動く瞬間があるか」なら、語頭・語尾・母音の移り変わりが必ず引っかかる。
  しかもこの判定は**「切らない」方向にしか効かない**ので、外しても失うのは削減率だけ。
- **形が動いているのは「声だから」ではなく「背景と混ざり方が変わるから」だった。**
  切り分けて測ると、背景まったく無しの合成の声は 0.017、雑音を 0.002 足すと 0.090。
  本物の録音には必ず背景があるので実用上は成り立つが、**理屈としては弱い**。
  そもそも合成の `speak()` は発話中ずっと倍音の重みも f0 も固定なので、
  形の上ではトレモロの楽器と同じものを「声」と呼んでいたことになる。ここは素材側の限界。
- **境界値でひとつ穴を見つけて塞いだ。** 必要な長さを固定 0.5 秒にしていたら、
  3 秒に切り詰めた素材で本物の声を弾いた（形が動いたのが 0.40 秒しかない）。
  ショート動画では 3 秒の素材は普通なので、尺の 5% まで下げるようにした。
- `npm run lab:uitest` が、確認は全部通るのに**終わらなくなっていた**。
  `npx` 経由で vite を起動していて、kill できるのが `npx` 側だけだったため。
  直接起動して集団ごと落とすようにした（19 項目すべて PASS、正常終了）。

**積み残し**

- 形の変化を、背景に頼らずに測る（フォルマントの動きを直に見る）。
- コマ単位で使える形にできれば、取りこぼし↔切れ味の曲線そのものを動かせるはず。
  素材単位に留めたぶん、`speech-sparse-bgm` の精度 40% → 81% は**取り逃している**。
- 合成の声が平板すぎる（`speak()` の既定は倍音固定のまま）。
- 試し用の素材はすべて自分で作った合成音。本物で試せていない。

### 2026-09-07（3 回目） — 取りこぼしを減らし、「声が見つからない」と言えるようにした

- 声らしさの判定にヒステリシス（入る 0.20 / 出る 0.10）を入れた。
- 声らしいところが見つからなければ**何もしない**ようにした（`noSpeechFound`）。
- 「BGM の上でたまにしゃべるだけ」の素材を追加。長尺（10 分）も測った。

**測った結果**

取りこぼし ↔ 切れ味（打楽器の上でしゃべる素材）:

| | 声を残せた率 | 精度 | 削減 |
| --- | --- | --- | --- |
| 平滑化なし・単一しきい値 | 85% | 95% | 50% |
| 平滑化なし・ヒステリシス | 88% | 92% | 47% |
| 平滑化あり・単一しきい値 | 92% | 91% | 44% |
| **平滑化あり・ヒステリシス（採用）** | **99%** | 87% | 37% |

新しい素材と長尺:

| 素材 | level → speech | 声を残せた率 |
| --- | --- | --- |
| ※ speech-sparse-bgm（BGM の上で 20% だけしゃべる） | **0% → 50%** | 100% |
| ※ drums（声なし） | 0% → **0%（何もしない）** | — |
| speech-long（10 分） | 34% → 34%、**6.4 秒 / 232MB** | — |

**分かったこと**

- **ヒステリシスは「より賢い仕組み」ではなかった。** 平滑化と比べたつもりが、
  測ってみると同じ取りこぼし↔切れ味の曲線の上にある別のつまみだった
  （88%/47% と 92%/44% はほぼ同じ点）。**併用すると片方では届かない所まで行ける**ので
  採用したが、「原理的に優れているから入れる」ではなかった。仮説は外れている。
- **いまのつまみはすべて同じ曲線の上にある。** 曲線そのものを動かすには、
  声らしさの出し方に別の手がかりを足すしかない。これは次の宿題。
- **「声らしいコマの割合」では音楽だけの素材を見分けられない。**
  音楽だけ 28% に対し、BGM の上でたまにしゃべる素材が 46%。線を引けば必ずどちらかを壊す。
  **自分の仮説を潰すために「たまにしゃべる」素材を先に作ったのが効いた**（作る前は
  「0.4 くらいで切れそう」と思っていた）。結局、機械に決めさせず、割合を返して
  人に知らせるだけにした。
- 長尺は杞憂だった。10 分で 6.4 秒（尺の 1.1%）。残る心配はメモリだけ。
- **いちばん実用に近いのは `speech-sparse-bgm`**（BGM の上でナレーション）で、
  ここが 0% → 50% になったのが今日のいちばん大きい収穫。

**積み残し**

- 音楽だけの素材を見分ける、割合ではない手がかり（区間の長さの分布など）。
- 取りこぼし↔切れ味の曲線そのものを動かす手。
- 試し用の素材はすべて自分で作った合成音。本物で試せていない。

### 2026-09-07（2 回目） — 音楽が乗った素材でも声を見分けられるようにした

- 意地悪な素材を 3 本追加（BGM が大きい / 4Hz で刻む打楽器の上でしゃべる / 打楽器だけ）。
  **狙って自分の手を潰しにいく素材**。これが無いと「効いた」の中身が確かめられない。
- `npm run lab:probe` を追加。正解の分かっている素材で、候補の特徴量を AUC で並べて比べる。
- 測った結果に基づいて `speech` モードを実装（`features.ts` / 自前 FFT / `silence.ts` のモード追加）。

**測った結果**

特徴量の比較（AUC、0.5 = 分けられない）:

| | きれいな声 | BGM 込み | ※BGM 大 | ※打楽器 | 平均 |
| --- | --- | --- | --- | --- | --- |
| 音量 | 1.000 | 0.888 | 0.650 | 0.805 | 0.891 |
| 揺れの速さ | 0.998 | 1.000 | **1.000** | 0.581 | 0.930 |
| 音色の尖り | 1.000 | 0.945 | 0.776 | **0.973** | 0.949 |
| **積（採用）** | 1.000 | 1.000 | **1.000** | **0.841** | **0.974** |

実際の効き（level → speech）:

| 素材 | 削減 | 声を残せた率 | 残したうち声だった率 |
| --- | --- | --- | --- |
| speech / quiet / noisy | 37〜38% → 37〜38% | 100% → 100% | 88〜89% → 88〜89% |
| speech-bgm | 27% → **38%** | 100% → 100% | 76% → **90%** |
| ※ speech-bgm-loud | **0% → 18%** | 100% → 100% | 55% → **67%** |
| ※ speech-drums | **0% → 44%** | 100% → **92%** | 55% → **91%** |

**分かったこと**

- **意地悪な素材を先に作ったのが効いた。** 「音量の揺れが 3〜6Hz か」を見る手は
  BGM に対して完璧（AUC 1.000）だったが、同じ速さで刻む打楽器には無力（0.581）。
  この素材が無ければ「うまくいった」で終わって、本物の音楽で崩れていた。
- **平均だけを見て選ぶと間違える。** 音色の尖り単体は平均 0.949 で悪くないが、
  苦手な素材での落ち込み（0.776）が大きい。積は平均も最悪値も良い。選ぶなら最悪値で見る。
- **AUC が上がっても実測が悪くなることがある。** 声らしさを移動平均で均したら
  AUC は 0.974 → 0.981 に上がったのに、実際の「声を残せた率」は 85% → 71% に落ちた。
  平均だと発話の端が周りに引きずられて下がるため。最大値で谷だけ埋める形に変えた。
  **指標を増やしたら、必ず実測でも確かめる。**
- **削減率だけを見てはいけない。** 全部削れば削減 100% になる（実際 `drums.wav` がそうなった）。
  正解との一致率を bench に足すまで、この危うさに気づけていなかった。
- 谷を埋める窓の広さは、取りこぼしと切れ味の素直な交換になっていた
  （窓なし 85%/95% … 0.25 秒 100%/76%）。**声を切るのは取り返しがつかない**ので
  取りこぼさない側へ寄せて 0.10 秒にした。

**積み残し**

- `speech` モードは打楽器の上で声を 8% 取りこぼす。窓の広さで交換しているだけなので、もっと素直な手があるはず。
- 声の無い素材（音楽だけ）に掛けるとほぼ全部削る。「見つからなかった」と言う道が要る。
- 試し用の素材はすべて自分で作った合成音。本物で試せていない。
- 長尺（10 分）はまだ測っていない。

### 2026-09-06 — ラボを作り、無音カットとオートダッキングを試作

- `lab/` を作成。本体のビルドからは完全に切り離してある。
- `lab/auto-cut` に、20ms ごとの音量の列を共通の材料として
  **無音カット（ジェットカット）・オートダッキング・波形表示**の 3 つを実装。
- コマンドラインから走るセルフテスト 20 件（`npm run lab:test`）。ブラウザもサーバも要らない。

**分かったこと**

- しきい値を固定値（-40dB など）にすると、録音レベルの違う素材でまったく効かない。
  素材ごとの音量の分布（下位 10% を無音の底、上位 10% を声）から決めるようにしたら、
  合成素材で自動的に -46.7dB が選ばれて素直に効いた。
- パラメータは 3 つ（感度 / 短い無音は残す / 前後の余白）で足りる。
  それ以上出すと、どれを触ればいいか分からなくなる。
- 判断する関数を DOM から切り離しておくと、Node が `.ts` をそのまま実行できるので
  テストがブラウザ無しで回る。ここは以降も守る価値がある。

**積み残し**

- 音楽が乗った素材では使えない（上の候補の 1 つ目）。
- 長尺での処理時間・メモリはまったく測っていない。
